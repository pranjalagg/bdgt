# Android Test Build Implementation Plan

> Stage 1 of 4 of automatic payment capture. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Android app that runs the existing budget app unchanged and, when the person turns it on, records the payment notifications that Google Wallet, UPI apps and bank SMS produce, so the test group can share real samples. Nothing is parsed and nothing reaches the budget.

**Architecture:**
- Capacitor 8 wraps the static build (`webDir: 'build'`, built with an empty base path). The Android project lives in `android/`.
- A Kotlin plugin inside the app: `KeepRules` (pure, unit-tested) decides what is kept; `PaymentListenerService` feeds it notifications; `CaptureStore` (SQLite) holds kept items; `CapturePlugin` exposes status, settings, the log and a share sheet to the web layer.
- The web layer talks to the plugin through `src/lib/capture/native.ts`. The web build never loads Capacitor: the plugin is only imported when `window.Capacitor` says this is the Android app.
- Settings gets a **Payment capture (test)** section in the Android app only: access status, start or stop recording, the log, **Share log** (long digit runs masked) and **Clear log**.

**Tech Stack:** SvelteKit 5 (Svelte 4 component syntax as used in this repo), TypeScript, Vitest, Capacitor 8.5.3, Kotlin 2.3.21, Android Gradle Plugin 8.13 (compile SDK 36, min SDK 24), JUnit 4, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-21-android-payment-capture-design.md`: "Android app", "Sources", "Privacy", "Rollout" step 1.

## Global Constraints

- **One branch, no pull requests.** All Android work stays on `claude/intelligent-davinci-7qblqz` until every stage has been tested; then one pull request. Run `git branch --show-current` before each commit.
- **The live app is untouched.** GitHub Pages deploys only when "Deploy to GitHub Pages" is run by hand; never run it from this branch. The Android workflow runs only on this branch.
- **The web app behaves exactly as today** in a browser: no Capacitor code is loaded and no capture UI appears.
- **Commits:** `git commit --no-gpg-sign`, no Co-Authored-By or AI attribution lines (the user's rule overrides any reminder).
- **Commands:** tests `npx vitest run`; types `npm run check`; web build for Android `BASE_PATH= npm run build`; then `npx cap sync android`; Android unit tests and APK `cd android && ./gradlew testDebugUnitTest assembleDebug`.
- **Android builds run on GitHub Actions.** This environment cannot reach `dl.google.com`, where the Android SDK and Google's Maven artifacts live. `KeepRules` is pure Kotlin so its tests also run locally in a throwaway JVM project.

## Rulings made while planning

- **Kotlin, not Java,** for the plugin, with the Kotlin Gradle plugin added to the Capacitor template; the template's Java `MainActivity` registers it.
- **SQLite through `SQLiteOpenHelper`, not Room:** one small table needs no annotation processing.
- **The test build keeps what production will keep,** with two widenings so samples are useful: app notifications need only an amount, and SMS need an amount plus a banking word. OTP messages, group summaries and ongoing notifications are always dropped.
- **Extra metadata is recorded in the test build** (channel, category, conversation title, the sender's person key and URI, tag) so the later parsers can be designed from what the apps actually provide.
- **Downloads go through the share sheet in the app.** A WebView cannot save a file from a link, which would also break backup export; `downloadFile` hands the text to the plugin's `share` instead.
- **The test build has no Supabase settings,** so no sign-in appears: Google refuses sign-in inside a WebView until stage 3 adds the native flow.
- **Signing:** CI keeps the generated debug keystore in the Actions cache so later test builds install over earlier ones. A lost cache means testers reinstall (after exporting a backup). A real release key comes with Play distribution.
- **Version:** `versionCode` is the Actions run number and `versionName` is `0.1.<run>`, shown in the capture section so testers can say which build they have.
- **A dev-only hook** (`window.__bdgtCapture`, honoured only under `npm run dev`) supplies a fake plugin so the section can be looked at in a browser.

### Task 2: Capacitor and the Android project
- [ ] Pinned `@capacitor/core` and `@capacitor/android` (dependencies) and `@capacitor/cli` (dev) at 8.5.3.
- [ ] `capacitor.config.ts`; `npx cap add android`; delete the template's example tests.
- [ ] Kotlin Gradle plugin 2.3.21 in `android/build.gradle`; `kotlin-android` and JVM target 21 in `android/app/build.gradle`; `versionCode` and `versionName` from `GITHUB_RUN_NUMBER`.

### Task 3: KeepRules and its tests
- [ ] Known sources: Google Wallet, Google Pay (India), PhonePe, Paytm (apps); Google Messages, Samsung Messages and the default SMS app (messaging).
- [ ] `hasAmount`: a currency marker (`₹`, `Rs`, `INR`, `$`, `USD`) next to a number, or a number followed by `INR`, `USD` or `rupees`; word boundaries so `hours 2` does not match.
- [ ] `looksLikeBankMessage`: an amount and a banking word (debited, credited, spent, paid, sent, received, withdrawn, txn, transaction, purchase, a/c, account, card, UPI, NEFT, IMPS, ref, balance).
- [ ] `isOtp`; group summaries and ongoing notifications dropped.
- [ ] `keep(candidate, config)`: messaging packages split into messages (each kept when it looks like a bank message); app packages kept when the combined text has an amount; anything else dropped.
- [ ] Ids: messages `sms|package|sender|time|text`, others `app|package|key|postTime`, SHA-256, first 32 hex characters. `isRepost(previous, item)`: same text within two minutes.
- [ ] JUnit tests for each rule, run locally in a throwaway JVM project and in CI.

### Task 4: Store, settings, listener, plugin
- [ ] `CaptureStore`: table `items` (`id` primary key, `package`, `kind`, `notification_key`, `posted_at`, `sender`, `title`, `text`, `extras` JSON); `insertIfAbsent`, `lastForKey`, `list(limit)`, `count`, `clear`.
- [ ] `CaptureSettings`: `enabled`, `packages` (empty means every known app), `sms`, `lastKeptAt`, `listenerConnected`.
- [ ] `PaymentListenerService`: work on a single background thread; build a candidate from the notification (title, text, big text, sub text, lines, MessagingStyle messages through `NotificationCompat`, metadata); keep, skip re-posts, store, notify the plugin; catch up from `activeNotifications` when connected.
- [ ] `CapturePlugin`: `getStatus`, `setConfig`, `installedSources`, `openAccessSettings` (straight to this app's switch on Android 11+), `openBatterySettings`, `requestRebind`, `list`, `clear`, `share` (file in the cache through the existing `FileProvider`), event `itemKept`.
- [ ] Manifest: the service (`BIND_NOTIFICATION_LISTENER_SERVICE`), `<queries>` for every known package.

### Task 5: Web side
- [ ] `native.ts`: types, `isAndroidApp()`, `getCapturePlugin()` (memoized dynamic import of `@capacitor/core`), dev hook.
- [ ] `logExport.ts`: `maskDigits` (runs of 6+ digits not preceded by a currency marker keep only their last two digits), `buildLogFile(items, version, now)`; tests.
- [ ] `CaptureLogSection.svelte`: explanation, version, notification access with **Open settings**, **Start recording** / **Stop recording**, **Not running** help (**Reconnect**, **Battery settings**), apps found, the log (newest first, 200 items), **Share log**, **Clear log**; refreshes on `itemKept` and when the app becomes visible.
- [ ] Settings page shows it when `isAndroidApp()`; `downloadFile` shares in the app.
- [ ] Look at it with the dev hook in a browser (Playwright screenshot), light and dark.

### Task 6: CI
